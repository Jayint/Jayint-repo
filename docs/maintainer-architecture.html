EnvState v1 — The Maintainer

What it maintains, and how auto_resolve + error/stdout parsing work. Boxes are color-coded by who writes. Every claim is anchored to file:line.

Host — deterministic (facts) LLM Maintainer (interpretation) Structural (done_flag) Set once (cycle 0) Planner BuildAgent
One idea to hold onto: the “Maintainer” is two writers, not one agent. A deterministic host half (apply_deterministic + _auto_resolve_*) owns the facts and certifies what is true; an LLM half (Maintainer.update) owns the interpretation — it reads failures and writes open_problems/notes. The LLM proposes; the host certifies.

The model’s whole job is one task it’s good at: “given this output + these known facts, what failed and at which layer?” It tags each failure layer ∈ {base, system, runtime, deps, build, tests} (default deps maintainer.py:104). That layer label is what makes auto_resolve possible.

4 · auto_resolve — the host un‑saying what the LLM said

Inside apply_deterministic world_model.py:297‑298: two sequential passes that drop problems the latest probe proves fixed. Pass 2 runs on pass 1’s output. Both are conservative — unknown shapes are kept.

pass 1 pip / deps — _auto_resolve_problems world_model.py:198‑218
# names from the `installed` facts
names = [f.name.lower() for f in installed]   # {"flask","psycopg2"}
for p in open_problems:
    if any(name in p.signature.lower() for name in names):  # SUBSTRING
        drop p   # resolved
"ModuleNotFoundError: flask" + flask∈installed ⇒ DROPPED.
remaining problems
▼
pass 2 system layer — _auto_resolve_system_problems world_model.py:239‑266
# only problems with layer == "system"
present = {names in system_installed}            # {"pg_config","libpq"}
present |= {strip "lib" prefix}   # libpq → pq   (L254)
present |= {add   "lib" prefix}   # pq → libpq   (L255)
for p in system_problems:
    art = _system_artifact(p.signature)   # regex, see §5
    if art in present:  drop p
"pg_config: command not found" + pg_config∈system_installed ⇒ DROPPED.
Why two passes? A pip miss is checked against pip list facts; a system miss (pg_config not found, cannot find -lpq) is checked against dpkg/pkg-config/PATH facts. Different sources → different matching → two functions.
Watch‑outs: pass 1 is a substring match (conservative, but psycopg2 vs psycopg2‑binary falls through to the LLM’s own resolved). Pass 2 matches the artifact (pg_config), not the apt package (libpq‑dev); L263 uses art.replace("lib","") — a global replace, not prefix‑strip.

5 · Error / stdout parsing — two directions meeting at the signature

There’s no single “parser”. Raw output flows two ways; they meet at the signature string. (diagnostics.py is not a parser — it only logs LLM exchanges.)

direction A probe output → FACTS
Deterministic, every cycle.
read‑only commands extractor.py:15‑34
pip list --format=freeze · dpkg -l · pkg-config --list-all · command -v gcc make pg_config…
▼ rc==0 & non‑empty only — extractor.py:56
probe_env() → EnvSnapshot snapshot.py:52‑75
  • _parse_installed → installed = (Fact"flask","3.0.0", …)
  • dpkg/pkgcfg/tools → system_installed
  • scalars → env (bulky lists stripped)
empty env ⇒ probe failed ⇒ apply_deterministic keeps prior facts (graceful degrade).
direction B failure output → SIGNATURE
LLM interprets, then host regex re‑extracts.
raw TaskReport.commands[*].output
“Building wheel… pg_config: command not found”
▼ LLM interprets arbitrary errors
OpenProblem
signature      = "pg_config: command not found"  ← KEY
interpretation = "psycopg2 build needs libpq"
layer          = "system"
▼ _system_artifact() — world_model.py:222‑236
4 regexes extract the artifact token
# signature → artifact
…(command not found| : not found)   → pg_config
no package '([^']+)' found          → libpq
cannot find -l(\S+)                 → pq
fatal error:\s*([\w./+-]+)\.h       → libpq-fe
The pivot: the signature is written by the LLM in human‑readable error form, and read back by the host regexes into a normalized artifact token — so the deterministic side (§4) can match it against probe Facts and auto‑resolve it. It is simultaneously a stable dedup key and a regex‑parseable handle.

6 · The whole thing, as one loop

llm observes failure → writes OpenProblem(signature, layer)
▼
planner turns the open problem into a task
▼
buildagent acts — installs the missing thing
▼
host re‑probe → auto_resolve: signature ∈ facts? → drop problem → progress[] ratchets up
▼
structural pytest --collect-only exits 0 → done_flag → loop stops

The Maintainer is the bookkeeper of that loop: the LLM says what broke, the host proves what’s fixed, and the map stays honest.
