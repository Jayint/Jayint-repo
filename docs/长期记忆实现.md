# 长期记忆机制实现说明

本文档记录当前代码中如何接入长期记忆机制。设计目标是：在不影响默认运行路径的前提下，让环境配置 agent 在命令失败后可以主动检索历史经验，并在成功完成 setup 后从完整轨迹中生成新的长期记忆。

## 启用方式

长期记忆默认关闭。只有显式传入参数时才启用：

```bash
.venv/bin/python run_verified_regression.py \
  --dataset single.jsonl \
  --output-root outputs/verified_regression_memory \
  --enable-observation-compression \
  --enable-long-term-memory
```

可选参数：

```bash
--memory-path memory/long_term_memories.jsonl
--memory-embedding-model BAAI/bge-base-en-v1.5
```

依赖安装：

```bash
.venv/bin/python -m pip install -r requirements.txt
```

第一次真正调用 embedding 时，`sentence-transformers` 会自动下载 `BAAI/bge-base-en-v1.5` 到本地缓存。

## 主要代码改动

`src/memory_manager.py`

新增长期记忆管理模块，负责：

- 读取和写入 `memory/long_term_memories.jsonl`
- 根据失败命令和失败 observation 构造英文检索 query
- 调用本地 embedding 模型计算向量
- 对 query 和已有记忆做 cosine similarity 检索
- 把检索结果格式化成下一轮 Observation
- 在成功 run 结束后调用 LLM 从最终 setup log 中提取长期记忆候选
- 写入新记忆时计算 embedding，并用 embedding 相似度召回可能相关的已有记忆
- 对候选相似记忆调用 LLM relation judge，判断 `duplicate` / `link` / `unrelated`
- 对 `duplicate` 拒绝写入新记忆，对 `link` 建立双向 `linked_memories`，对 `unrelated` 不连边

`src/constants.py`

新增默认 embedding 模型：

```python
DEFAULT_MEMORY_EMBEDDING_MODEL = "BAAI/bge-base-en-v1.5"
```

`requirements.txt`

新增：

```text
sentence-transformers>=3.0.0
```

`src/planner.py`

新增 `enable_long_term_memory` 参数。只有开启长期记忆时，system prompt 才会加入：

```text
Action: <bash command to execute, __ROLLBACK__, or __RETRIEVE_MEMORY__>
```

并加入一个很短的工具说明：agent 只能在具体命令失败后输出 `Action: __RETRIEVE_MEMORY__`，检索结果只是建议，必须继续通过真实命令和测试验证。

`agent.py`

新增 `enable_long_term_memory`、`memory_path`、`memory_embedding_model` 参数。

开启后，初始化：

```python
LongTermMemoryManager(
    client=self.client,
    llm_model=model,
    memory_path=self.memory_path,
    embedding_model=self.memory_embedding_model,
)
```

执行循环中新增特殊 action：

```text
Action: __RETRIEVE_MEMORY__
```

该 action 不进入 sandbox，不执行 bash，不记录 Dockerfile，也不影响 verification block。它只根据最近一次失败上下文调用 `memory_manager.retrieve(...)`，并把检索结果作为下一轮 Observation 返回给 agent。

当普通命令失败时，系统会记录：

```python
{
    "command": action,
    "observation": prompt_observation,
    "repo_url": self.repo_url,
    "services": sorted(self.required_local_services),
}
```

成功完成环境配置并生成 Dockerfile 后，系统会读取最后一个 `setup_logs/*.md`，调用 `memory_manager.generate_memories_from_run(...)` 生成候选长期记忆。只有 LLM 输出的候选通过结构校验后，才会被写入 JSONL。

`run_verified_regression.py`

新增 CLI 参数，并把参数传给 adapter：

```text
--enable-long-term-memory
--memory-path
--memory-embedding-model
```

`multi_docker_eval_adapter.py`

把长期记忆相关参数继续传给 `DockerAgent`，并在结果 JSON 中保存：

```json
"memory_stats": {
  "enabled": true,
  "retrievals": 0,
  "retrieval_hits": 0,
  "generation_attempted": true,
  "candidate_memories": 0,
  "written_memories": 0,
  "skipped_duplicates": 0,
  "skipped_invalid": 0,
  "relation_judged_pairs": 0,
  "relation_links_accepted": 0,
  "relation_links_rejected": 0,
  "relation_duplicates_rejected": 0,
  "errors": []
}
```

`src/observation_compressor.py`

在 `RunTokenLedger` 中新增 `memory` bucket，用于统计长期记忆生成阶段的 LLM token 消耗：

```python
memory: TokenBucket = field(default_factory=TokenBucket)
```

## 运行时流程

失败后检索流程：

```text
1. 普通 bash 命令失败
2. agent.py 记录最近失败命令和压缩后的失败 observation
3. agent 下一轮如果判断需要长期记忆，输出 Action: __RETRIEVE_MEMORY__
4. agent.py 拦截该特殊 action
5. memory_manager 构造英文 query
6. embedding 模型计算 query embedding
7. 读取 JSONL 里已有记忆，与 memory["embedding"] 做 cosine similarity
8. 返回 top-k 相关记忆摘要
9. agent 根据检索结果继续执行真实 setup 命令
```

成功后写入流程：

```text
1. agent 输出 Final Answer: Success，并提供 Verification Bundle
2. agent.py 生成 Dockerfile
3. agent.py 读取最后一个 setup log
4. memory_manager 用 LLM 从完整 setup 轨迹中提取长期记忆候选
5. 如果候选满足“反复失败后最终解决”的写入条件，则计算 embedding
6. 与已有记忆做 embedding 相似度召回，得到可能相关的 top-k 候选记忆
7. 对每个候选边调用 LLM relation judge，判断 `duplicate` / `link` / `unrelated`
8. 如果 judge 判断为 `duplicate`，拒绝写入新记忆；如果判断为 `link`，建立双向链接；如果判断为 `unrelated`，不连边
9. 写入 memory/long_term_memories.jsonl；如果旧记忆链接被更新，则重写 JSONL 文件以保持双向边
10. token 消耗和写入统计记录到 agent_run_summary.json
```

关系判定细节：

```text
1. 新记忆先用 scope + repo + problem_signature 做确定性去重
2. 如果确定性 key 不重复，则计算新记忆 embedding
3. 系统用 embedding 从已有记忆中召回超过阈值的候选记忆
4. 每个候选对都会交给 LLM relation judge
5. relation judge 只能返回 duplicate、link 或 unrelated
6. duplicate 表示新旧记忆描述同一个问题，系统拒绝写入新记忆
7. link 表示两条记忆相关但不同，系统写入新记忆并建立双向边
8. unrelated 表示 embedding 误召回，系统写入新记忆但不连边
```

如果没有 LLM client 或没有配置 LLM model，系统会退回到 embedding 阈值连边。这个 fallback 主要用于离线测试、人工导入和初始化记忆，正常运行时应优先使用 relation judge。

初始化记忆：

- 从 prompt 迁移出来的经验性规则直接写入 `memory/long_term_memories.jsonl`
- 这些记忆使用 `source: "prompt_migration_seed"` 标记
- 初始化记忆不维护单独的 seed 文件，避免运行时需要合并两套记忆源
- 写入方式与普通长期记忆一致：计算 embedding、去重、通过 relation judge 过滤重复/误连，并生成双向 `linked_memories`

## Embedding 调用方式

当前使用本地 `sentence-transformers`：

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-base-en-v1.5")
embedding = model.encode([text], normalize_embeddings=True)[0]
```

query 会加 BGE 检索前缀：

```text
Represent this sentence for searching relevant passages:
```

记忆的 `embedding_text` 不加前缀，直接编码。

## 记忆存储格式

第一版使用本地 JSONL，不引入 SQLite、Faiss、Qdrant 或 Chroma。

默认路径：

```text
memory/long_term_memories.jsonl
```

LLM 只生成语义字段，不生成 embedding。系统写入时会补充内部字段：

```json
{
  "scope": "ecosystem",
  "repo": "repo_name",
  "problem_signature": "...",
  "symptoms": [],
  "root_cause": "...",
  "successful_fix": [],
  "verification": [],
  "anti_patterns": [],
  "embedding_text": "...",
  "linked_memories": [],
  "created_at": "...",
  "embedding": [0.012, -0.034],
  "embedding_model": "BAAI/bge-base-en-v1.5"
}
```

`embedding` 和 `embedding_model` 是系统内部字段，不要求 LLM 输出。

## 日志与统计

长期记忆生成日志写在当前 run 的：

```text
workplace/<instance>/logs/setup_logs/memory_generation.md
```

该文件记录：

- memory extraction 的输入 prompt
- LLM 输出的原始候选记忆
- 解析后的候选记忆
- 写入结果，包括写入数量、跳过数量、relation judge 统计和错误信息
- memory extraction 阶段的 token 消耗

relation judge 的 token 消耗会合并进本次 memory token bucket，最终写入 `agent_run_summary.json` 的 `token_usage.memory`。

当前统计字段：

```json
{
```

## 如何查看运行效果

查看本次 run 的长期记忆状态：

```bash
python - <<'PY'
import json
p = "workplace/multi_docker_eval_Spomky-Labs__otphp-166/agent_run_summary.json"
d = json.load(open(p))
print(json.dumps({
  "enabled": d.get("long_term_memory_enabled"),
  "memory_path": d.get("memory_path"),
  "embedding_model": d.get("memory_embedding_model"),
  "memory_stats": d.get("memory_stats"),
  "memory_token_usage": d.get("token_usage", {}).get("memory"),
}, indent=2, ensure_ascii=False))
PY
```

重点看：

- `retrievals`：agent 触发了几次 `__RETRIEVE_MEMORY__`
- `retrieval_hits`：检索返回了几条相关记忆
- `generation_attempted`：成功后是否尝试生成记忆
- `candidate_memories`：LLM 输出了几条候选记忆
- `written_memories`：实际写入了几条
- `relation_judged_pairs`：有多少对候选相似记忆交给 LLM 判断
- `relation_links_accepted`：LLM 确认应该建立连接的数量
- `relation_links_rejected`：LLM 判断为 embedding 误召回、不应连边的数量
- `relation_duplicates_rejected`：LLM 判断为语义重复并拒绝写入的数量
- `errors`：下载模型、embedding、JSON 解析或写入是否出错

查看记忆库：

```bash
wc -l memory/long_term_memories.jsonl
tail -n 3 memory/long_term_memories.jsonl
```

## 回退方式

最简单回退方式是不传：

```bash
--enable-long-term-memory
```

不开启时：

- planner prompt 不包含 `__RETRIEVE_MEMORY__`
- 不初始化 `LongTermMemoryManager`
- 不加载 embedding 模型
- 不读取或写入 `memory/long_term_memories.jsonl`
- 原有 setup、压缩和评估逻辑保持不变

如果只想清空记忆库，可以删除或移动：

```text
memory/long_term_memories.jsonl
```
