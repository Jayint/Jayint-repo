◢ the core split

Run-as-config vs recipe-as-output

RAT hands back the configured container — the trajectory is the environment. DockerAgent treats the trajectory as evidence, then synthesizes a separate Dockerfile and re-validates it clean-room.

◢ planning model

Prompt-driven, both

Neither has a standalone planner module. RAT’s “plan” lives in the system prompt (or a self-edited plan.md); DockerAgent’s lives in a strict one-action planner prompt + a Verification Bundle.

◢ what compounds

Memory & rollback

DockerAgent adds two things RAT lacks: cross-run RAG memory and image-snapshot rollback. RAT keeps it leaner — history only, session-restart on timeout.

◢ same foundation

Custom ReAct, no framework

Strip the orchestration and both are the same primitive: a hand-written ReAct loop over openai.chat.completions, regex-parsed text actions, one Docker container. The differences are all in the wrapping.
