The loop’s only persistent state. The agent reads it with cat and rewrites it with edit-file each turn. No host code touches it.
◢ where it lives

One prompt, two phases

The two-phase workflow is text in _get_custom_plan_prompt (python_config.py:218). There is no separate planner module — the “plan loop” is the ReAct loop reading a file.

◢ routing signal

The file is the state machine

Each turn the agent cat /repo/plan.md and branches on existence + checkbox state. Create vs execute vs stop is the agent’s call, not the host’s.

◢ created once

Guarded by existence

Phase 1 fires only “if the file doesn’t exist,” so plan.md is written once on turn 1, then only updated. Convention, though — nothing in code enforces it.

◢ survives timeouts

Persists across the run

On timeout the bash session restarts (codeagent.py:441), not the container — so /repo/plan.md lives for the whole run. One container = one plan.

Code: loop = codeagent.py:367 (while turn < max_turn) · prompt = python_config.py:218–314 (_get_custom_plan_prompt) · selected by use_custom_plan (CLI --custom-plan, env_main.py:152).
Reminder: the RAT benchmark (rat_model.py) never sets use_custom_plan → it runs Standard mode, where the “plan” is a fixed numbered list baked into the prompt, with no plan.md.
