### Iteration 1 — Finding A: emit the repo's own editable install (render)
- **Observation:** every rendered `setup.sh` installed the pinned dependency closure but never the repo under test; src-layout repos (postgres_mcp under `src/`) then failed `import <own_pkg>` despite a "clean" install.
- **Why:** `render_build_script` only emits nodes where `emit._is_reciped` is true (Package w/ version, SystemLib/Tool w/ apt fix). The PROJECT node is neither, so `pip install -e .` was never rendered. Putting PROJECT in `_is_reciped` + Layer.PIP would NOT guarantee "last" — test/transitive packages with no edge to PROJECT can sort after it in topo tie-break.
- **What (paper-clean, ONE path):** installability decided once at construction (`_add_project_node` → `data["installable"]` iff pyproject.toml/setup.py present); command produced once by `populate._command_for` (`…--no-deps -e .`, build isolation ON so pip fetches the PEP517 backend the closure omits); emitted once by `render_build_script` as a dedicated FINAL `# PROJECT (editable)` section — deliberately NOT in `_is_reciped` (avoids per-layer double-emit and guarantees after-all-deps). `render_fidelity` gains `editable_last`. Surfaced+fixed a probe bug: the coverage execution probe ran `setup.sh` from `/`, breaking `-e .`; now runs from the repo root (the standard contract). New `srclayout_editable` edge case.

### Iteration 2 — Finding C: discover subprocess-invoked CLI tools (construction)
- **Observation:** external CLI programs a repo's own code shells out to (mvt's `sqlite3`, and adb/git/java/ffmpeg generally) never appear in the graph — the env then lacks them and the code fails at runtime with FileNotFoundError.
- **Why:** system-dep discovery is ldd-based (`ldd_probe` finds shared LIBRARIES linked into compiled `.so`s) + pip-build tools; a standalone binary the code merely `subprocess`-es is invisible to both.
- **What (paper-clean, conservative):** new pure `subprocess_scan.py` — AST-scans in-scope `.py` (reusing `config_scan`'s exclusion scope) for `subprocess.*` / `os.system` / `shutil.which`, extracts argv[0] (list, shell-string, or path→basename). STRICT allowlist `tables.CLI_TOOL_TO_APT` (kept DISJOINT from the build-tool `TOOL_TO_APT` so one apt pkg can't mint two nodes) is the false-positive backstop — unknowns/builtins/coreutils/local scripts/variable commands never flag. `add_subprocess_tool_nodes` mints `tool:<name>` TOOL nodes (apt fix, `command -v <t>` check, tool-name-is-id per ldd_probe's canonical rule) hung off the Project anchor; wired as build.py Stage 3a''.
- **Verification:** 11 scanner unit tests (incl. `== {}` false-positive teeth) + a FakeExecutor build-level integration test (adb→node w/ `apt:adb`, MISSING, Project edge); `tests/depgraph`+`tests/eval`+`tests/envstate` 980 green. Real mvt scan → `sqlite3` (a true, previously-missed gap). Honest correction: mvt does NOT subprocess adb/git/java (Python `adb-shell` lib), so they're correctly not flagged; the synthetic `subprocess_cli_tools` edge case carries the adb/git/sqlite3 known-answer. Commit 194d6ee.
